## 1. 絶対制約（07章 §7.1 ガードレール）

以下に**1つでも**触れる投稿は、エージェント単独では公開しない。下書き化のみ。

1. 自演レビュー / サクラ / フォロワー購入 / なりすまし → **永久禁止**。
2. 未実装機能を実装済みのように語る、存在しない素材を貼る、実績・引用・受賞の捏造 → **永久禁止**。
3. ゲーム映像と称する素材は **実ビルドの実画面に限る**。モック・生成画像をビルド画面として出さない。
4. 各媒体の自動化規約（X の自動投稿制限、Reddit の自己宣伝規約、Discord の bot 規約等）を逸脱する操作はしない。
5. AI 運用であることを問われたら正直に答える。**隠さない／前面に出す必要もない**（自然体）。
6. 政治・宗教・時事論争・他作品/他者への否定的論評には乗らない。
7. 古ノルド/北欧神話は **史実と創作を明確に区別**して敬意をもって扱う。

## 3. エージェント / 人間 の権限分担（07章 §7.5 圧縮版）

## 4. コンテンツ4本柱（投稿は原則これのいずれか）

比率目安 **4 : 3 : 2 : 1**。

1. **フック（4）**: 古ノルド語の解読 → 魔法の "アハ" 瞬間を 15〜30 秒で。最重要資産。
2. **devlog / ビルドインパブリック（3）**: 実装の進捗・失敗・暴発の珍事。ソロ開発の物語＝真正性資産。
3. **言語 / 神話の小ネタ（2）**: 例「`fjandi`＝敵、語源は『憎む者』」。`03` 附録A 裏取り済みを一次ソースに。
4. **コミュニティ / 節目（1）**: ウィッシュリスト解禁・デモ・Next Fest・マイルストーン。CTA は常に **ウィッシュリスト**。

## 5. ボイス・トーン

- 一人称は **開発者本人**。エージェントは代弁者であって別人格を演じない。
- 知的だが衒学的でない。ソロ開発の率直さ。誇張・煽り・過剰絵文字を避ける。
- 日本語先行、英語はメイン市場（`01` §6.1）。**フック動画は言語非依存**を優先。
- 英語投稿は平明・簡潔（学習補助と同じ方針 ＝ `03` 附録B 注記）。
- 禁止表現: 「世界を変える」式の誇大、競合の貶め、AI運用を隠した人間ふり。

## 6. アセット要件

- フック動画 / GIF は **実ビルド** から（INC-2 以降）。
- **1メッセージ = 1フック**。説明を盛らない。
- 字幕・テキストは最小限・**言語非依存に寄せる**。
- ルーン字形がモバイル環境で豆腐化しないか必ず実機確認（`04` フォント制約と一致）。
- 画像にはコントラスト・読みやすさ配慮。

## 7. ハッシュタグと言及（既定セット）

INC-1 通過後の解禁を前提に、最初に整える既定タグ群:

- 日本語側: `#インディーゲーム` `#ゲーム制作` `#個人開発` `#Godot`
- 英語側: `#indiedev` `#gamedev` `#solodev` `#roguelike` `#Godot`
- テーマ側: `#OldNorse` `#古ノルド語` `#runes` `#NorseMythology`

> 1投稿あたり **タグは3個まで**（多用はスパム判定リスク）。
> Reddit では別ルール（自己宣伝規約・コミュニティ別ガイド）に従う。本ポリシーは X 既定。

## 8. KPI（07章 §7.8 圧縮）

- **主 KPI**: Steam ウィッシュリスト純増（週次）。
- 副指標: フック動画の視聴維持率／拡散、Steamページ遷移率、デモ DL／プレイ時間／離脱点。
- **虚栄指標**（フォロワー総数、いいね数）単独で意思決定しない。
- 週次レビュー（人間、15分）: 何が刺さったか／次週の柱配分／エスカレーション棚卸し。

## 9. インシデント対応フロー

エージェントが投稿または下書きを通じて**炎上・ネガティブ反応・誤情報の指摘**を察知した場合:

1. **公開反応は止める**（自動返信を切る）。
2. 状況要約（発端ポスト URL・反応の量・主要な指摘点）を 5 分以内に人間へ提示。
3. 人間が方針決定（謝罪／訂正／無視／コミュニティ向けポスト）するまで、関連トピックの新規投稿は凍結。
4. 訂正が必要な場合、**元投稿の削除より引用訂正を優先**（透明性）。

## 10. 記録・監査

- 全公開投稿、主要エンゲージメント（10 RT または 50 いいね超のもの）、人間承認の経緯を週次でログ化。
- ログ置き場（推奨）: `D:\docs\sns\log\YYYY-MM-DD.md`。エージェントが起こし、人間がレビュー。
- 月次で 4 本柱の比率実績を点検。柱比率が大きくずれた場合は本ポリシーの更新を検討。

- 不一致が生じたら 07章を優先し、本ファイルを修正する（逆ではない）。
