## 推奨される読む順序

1. `01` でゲームの目標とコアループを把握する（**v0.9 マス目移動・グリッド戦術導入の大改訂済み**）
2. `03` でコアメカニクス(呪文文法)の挙動を理解する — **本作の成否はここに集中している**（**v0.18 範囲語・方向語コア化済み**）
3. `09` で Helgrind マップ仕様とシームレス戦闘の座標系・射程・方向の意味を把握する（**v0.1 新規**、INC-3 実装の土台）
4. `04` で Godot 上の実装構造を把握する（**v0.6 core/map/ 追加・dungeon_view 統合済み**）
5. `05` のスキーマ＋附録シードに従ってデータを足していく（INC-0 でシード投入）
6. `06` で INC-1 の検証ツール（spell_lab）と合否基準を把握する — **コアの面白さはここで判定**（**v0.2 INC-3.5 再判定章追加**）
7. `08` で INC-2 の戦闘層検証（**v0.5 INC-3.5 再判定章追加**）
8. `02` のバックログ優先度に沿って、毎反復「動く縦切り」を出しながら実装する（**v0.9 INC-3.5 新設済み**）
9. `07` で「届ける／売る」とSNS運用（エージェント実行）を、INC連動で並走させる

## 設計上の最重要原則（全ドキュメント共通の前提）

1. **理解度 = 制御精度であって威力ではない。** この一文がブレると本作は別のゲームになる。
2. **言語知識はプレイヤー（人間）に蓄積される。** ゲーム内の永続データは「ヒントの解禁度」に過ぎず、最終的にプレイヤー自身が暗記している状態をゴールとする。
3. **古ノルド語は実在言語に準拠する。** 創作語を混ぜない。語形変化（格・数・性）は文法規則として実装する。創作する場合は必ず「創作」と明示し、言語監修フェーズ（M5）でレビュー対象にする。
4. **縦切り優先。** 横に広げる前に「1呪文を詠唱して敵を倒し、死んで知識が残る」までを一気通貫で動かす。
