## 0. 旧辞典からの抽出方針（流用境界）

本書 v0.3 は別プロジェクトの辞典を参照元とする。**そのまま使わず、本作の設計に整合する部分のみ抽出**した。境界を明示する。

### 0.1 流用したもの（抽出・採用）
- **検証済み語彙**：原型・語源・品詞（語形変化型付き）・意味・カナ読み。さらに **CV / Zoëga / Wiktionary / ONP / Skaldic による文献裏取りと信頼度（✅◎⚠❓）**。→ 本作の「要 M5 言語監修」リスクを大幅低減（出典付きで採用可能）。
- **語クラス分類体系**：効果語／対象語／属性語／修飾語／範囲語／条件語／数値語／時間単位語／条件詳細語（／末尾語）。旧 v0.2 の簡易分類より精緻なため置換採用。
- **システム概念**：四大元素の合成（4 元素全部入りで「混沌属性」化）、修飾語の威力スケール、範囲語、`ef` ＋条件詳細語による条件詠唱の構造。

## 1. 設計原則（v0.2 から不変）

1. **威力は語の固有ティアで決まる。理解度は威力に影響しない。**
2. **理解度と文法的正しさは「制御精度」（ばらつき・暴発）に影響する。**
3. 文法は「罰」ではなく「情報」。失敗時はプレイヤーが**原因を特定できる**フィードバックを返す。
4. 文法スコープは学習設計（`01` 4章）と一対一対応。実装も学習段階順に解禁。
5. **語彙は出典付きで採用する。** 各語に文献裏取りと信頼度を持たせ `verified` を管理（`05`）。

## 2. 語クラス分類（旧辞典準拠に拡張）

| クラス | 役割 | 本作での文法上の扱い |
|--------|------|----------------------|
| 効果語（動詞 sögn） | 呪文の作用本体（害す/守る/癒す/弱める…） | 他動詞は目的語の**格**を要求（コアの格一致対象） |
| 対象語（名詞/代名詞） | 詠唱対象の指定（敵/自己） | 効果語の目的語。格を担う |
| 属性語（元素名詞） | 効果に属性を付与（火/水/風/土/光/闇） | 4 元素全部入り＝**混沌属性**化（特殊合成） |
| 修飾語（形容詞副詞用法） | 威力スケール（大/小） | 威力に乗算。語形は被修飾と一致が望ましい |
| 範囲語（v0.18 コアに昇格） | 効果範囲・射程・形状（近/遠/広/貫通） | **コア**: マップ座標系上で射程/形状を決定（`09 §7.1`） |
| 方向語（v0.18 コアに昇格、旧「末尾語」） | 対象方向の指定（前後左右） | **コア**: プレイヤーの向き基準で対象タイル決定（`09 §7.2`、`fram`/`aptr`/`vinstri`/`hœgri`） |
| 条件語 `ef` | 条件詠唱の導入 | 【ストレッチ】条件節を構成 |
| 条件詳細語 | 条件の中身（負傷/耐性/弱点…） | 【ストレッチ】`ef` と組む |
| 数値語 | 量（1/3/5/7…） | 【ストレッチ】持続/範囲の数量 |
| 時間単位語 | 持続単位（ひととき/時） | 【ストレッチ】数値語と結合し持続化 |

各語は理解度 `comprehension ∈ [0,100]` と固有ティア `tier ∈ {1,2,3}` を持つ（スキーマ `05`）。
**コア検証（INC-1〜INC-3）で扱うのは「効果語＋対象語＋格一致＋属性語＋修飾語＋範囲語＋方向語」。** v0.18 で範囲語・方向語をコアに昇格させたため、INC-3 以降は「位置あり詠唱」が常時行われる（`09 §6/§7`）。条件節 `ef`・数値語・時間単位語は引き続きストレッチ（§6）。

## 3. 呪文構文（文法）

### 3.1 基本文型（EBNF 風、v0.18 改訂）

```
spell        := [number time_unit] [condition] [range] [direction] [element] verb [modifier] object
condition    := "ef" cond_clause
cond_clause  := target cond_detail              # 例: sjálfr sárr（自身が負傷）
element      := element_word { element_word }    # 4元素全部で混沌属性
modifier     := "mikill" | "lítill"             # 性数格一致を要求 (§3.3 T8)
range        := "nær" | "fjarri" | "vítt" | "í gegnum"   # v0.18 コアに昇格
direction    := "fram" | "aptr" | "vinstri" | "hœgri"     # v0.18 コアに昇格（旧「末尾語」）
object       := target_word
verb         := effect_word
```

**v0.18 スコープ注記:**
- **コア（INC-1〜INC-3.5 で実装）**: `verb object` ＋ **格一致** ＋ **属性語** ＋ **修飾語（性数格一致）** ＋ **範囲語** ＋ **方向語**。
- **【ストレッチ】（INC-4 以降）**: `number time_unit` / `condition`(`ef`+条件詳細)。エンジンは将来これらを足せる構造（`04` の注入可能 ruleset）で作るが、コア検証時は ruleset で**無効化**して出さない。
- **INC-3 暫定**: 範囲語・方向語は **データには載せるが Validator では minor finding にとどめる**（コア違反扱いしない）。位置解決はタイル直接指定 UI のみ。INC-3.5 で本表のとおりコア違反扱いに格上げ（`09 §8`）。

コア検証で実際に扱う最小例（抽出語彙ベース）:
```
meiða fjanda           # 害す＋敵(対格)  → 格一致 → 命中
meiða fjandi           # 害す＋敵(主格)  → 格不一致 → 誤射（コア体験の核）
eldr meiða fjanda      # 火属性で敵を害す（属性語の補助スコープ）
lækna sjalfan          # 自らを癒す（対格・再帰）
```

ストレッチ到達形（旧辞典の条件詠唱を本作流に再構成。**コア検証では使わない**）:
```
ef sjálfr sárr  lækna sjálfr
（もし自らが負傷していたら、自らを癒せ）
```

### 3.2 正準語順（Canonical Order, v0.15 アイスランド語準拠）

**INC-1 正準形**:
```
[数値 時間単位] [ef 条件] [範囲] [属性] 効果語 [修飾] 対象語 [属性後置]
```

簡略形（INC-1 範囲・効果＋対象＋修飾＋属性のみ）:
```
[属性] 効果語 [修飾] 対象語
```
または属性後置（道具的）:
```
効果語 [修飾] 対象語 [属性]
```

**設計根拠（v0.15 改訂）**:
- 命令文 V-initial（古ノルド語／アイスランド語の命令文は動詞が文頭）。
- 形容詞は被修飾名詞の前置修飾（散文の標準）。
- 属性語は文頭副詞句または文末の道具的位置（与格的）に置く。effect と target の間には挟まない（名詞句の一体性を壊さないため）。

**判定（INC-1 で実装）**:
- effect → target の VO 順序（既存・コア）。
- modifier は target に隣接必須（前後どちらか、ただし前置を推奨）。
- element は effect の前 または target の後。effect-target 間に挟むのは NG。

**例**:
| 詠唱 | 判定 | 説明 |
|------|------|------|
| `meiða fjanda` | ◯ | 最小命令文 |
| `meiða mikinn fjanda` | ◯ | 修飾-名詞前置 |
| `eldr meiða mikinn fjanda` | ◯ | 属性前置 |
| `meiða mikinn fjanda eldr` | ◯ | 属性後置（道具的） |
| `meiða eldr mikinn fjanda` | ✗ | 属性が効果-対象の間 |
| `mikinn meiða fjanda` | ✗ | 修飾が動詞越しに離れる |
| `meiða fjanda mikinn` | △ | 修飾後置（INC-1 では NG として扱う） |

**ゲーム的扱い**:
- 正準語順 → **語順ボーナス**（既存、P_base に +15%）。
- 語順違反 → word_order finding（×6 暴発倍率）。
- 古ノルド語自体は語順自由だが、本作 DSL は「散文命令文として読める形」に絞る（学習目標として明確化）。詩型反見・倒置は INC-3 以降の「達人モード」候補。

### 3.3 文法一致規則（実装すべき判定）

| 規則 | 内容 | 違反時の既定挙動 | 区分 | INC-1 実装 |
|------|------|------------------|------|------------|
| 格一致 (case_agreement) | 他動詞の目的語は対格。`meiða fjanda`◯ / `meiða fjandi`✕ | 対象がブレる（誤射） | **コア** | ✅ 暴発 ×2 |
| 語順 (word_order) | 正準語順 `[属性] 効果 対象`。崩しは weight 大 | 効果が安定しない | **コア** | ✅ 暴発 ×6 |
| 属性合成 (elements) | 元素語の組合せ規則（4元素全部＝混沌属性、§A.3） | 半端な組合せは属性不発 | コア補助 | ✅ v0.13 暴発 ×1.5 |
| 修飾一致 (modifier, 最小) | 修飾語は効果語と並置で使う | 修飾語単独は構文エラー | コア補助 | ✅ v0.13 暴発 ×1.5（最小） |
| 修飾一致 (modifier_agreement) | 形容詞は被修飾語と性・数・格を一致させる | 修飾効果が減衰／不発 | **コア補助 (v0.14)** | ✅ v0.14 暴発 ×2.0 |
| 射程指定 (range_required, v0.18) | 詠唱が射程外の対象を狙わない（範囲語 or 暗黙隣接で射程内であること） | 「届かない」finding、ダメージ 0 | **コア (v0.18)** | INC-3 = minor finding、INC-3.5 = ×2 暴発 |
| 射程矛盾 (range_conflict, v0.18) | 範囲語の相互矛盾なし（`nær fjarri` 同時 NG 等） | range_conflict finding | **コア (v0.18)** | INC-3 = minor finding、INC-3.5 = ×3 暴発 |
| 方向指定 (direction_required, v0.18) | AoE / 貫通には中心方向の指定が必要（方向語 or タイル指定） | direction_required finding、対象未確定で詠唱不可（scaffold=max は事前ブロック） | **コア (v0.18)** | INC-3 = minor finding、INC-3.5 = ×2 暴発 |
| 範囲 (range, 旧表現) | 旧 v0.13 までの範囲語ストレッチ扱い | — | **v0.18 で `range_required`/`range_conflict` に分解** | — |
| 数一致 | 数値語と名詞/時間単位語の一致 | 持続/範囲値が乱れる | 【ストレッチ】 | ⏳ INC-4 以降 |
| 条件節構造 | `ef` の後に評価可能な条件詳細語 | 条件無視で無条件発動（危険） | 【ストレッチ】 | ⏳ INC-3 以降 |
| 否定スコープ | `eigi` 等の否定が掛かる範囲 | 効果が反転 | 【ストレッチ】 | ⏳ INC-3 以降 |

→ 判定結果は **`GrammarReport`**（規則ごと pass/fail と理由）。UI が人間可読フィードバックに変換（§7）。

**INC-1 v0.13 elements 判定の具体（コア補助）**:
- 0 元素: 判定対象外（無属性詠唱）。
- 1 元素: pass（属性付与成立）。
- 2-3 元素（四大の一部のみ）: fail / reason「半端な属性合成は不発します」/ severity minor。
- 4 元素全部 (eldr+vatn+vindr+jorth): pass / 情報メッセージ「混沌属性が発動」（finding は出さず effect_spec.modifiers["chaos"]=true をマーク、INC-2 で戦闘層が解釈）。
- ljos / myrkr が四大と混在: pass（光闇は混沌に参加しない）が `reason` 警告のみ。

**INC-1 v0.13 modifier 判定の具体（ストレッチ最小）**:
- 修飾語あり＋効果語あり: pass（Evaluator が P_base 乗算）。
- 修飾語あり＋効果語なし: fail / reason「修飾語は効果語と共に詠唱してください」/ severity minor。

**INC-1 v0.14 modifier_agreement の具体（コア補助に格上げ）**:
- 修飾語に形容詞活用表がある（`WordResource.has_gendered_inflection() == true`）場合、target の gender × case と一致するかを判定。
- 格不一致: fail / reason「`{mod_form}`（主格）は対象 `{target_form}`（対格）と性・数・格を一致させてください」/ recommended「`mikill` → `mikinn` ?」/ severity moderate / 暴発 ×2.0。
- 格一致だが活用形未定義（データ不足）: fail / severity minor / 警告メッセージ。
- 活用表が空の修飾語（形容詞活用を持たない副詞等）は INC-1 では判定対象外（INC-5 でカバー）。
- 動詞の命令法活用・名詞の複数形対応・強弱変化クラス分類等は INC-5 監修フェーズ（「達人モード」候補）。

**4 格データ（v0.14）**:
- 対象語・元素語の `inflection` に sg dat/gen を追加。CV/Zoëga 出典。INC-5 で複数形と全パラダイム精緻化。
- 形容詞 (mikill/litill) は `inflection.sg.{gender}.{case}` 形式で 12 形（性別 × 格）を保持。

> **本作の格運用ルール（重要）**：旧辞典は「数値語は格一致を要求しない」等の DSL 簡略を採っていた。本作は**コア体験が格一致なので、対象語については格一致を必須化**する。`fjandi`(主格)/`fjanda`(対格)、`sjálfr`(主格)/`sjalfan`(対格・再帰) のように対象語は格変化表をデータで持つ（`05` の `WordResource.inflection`）。属性語・数値語・末尾語は格一致を要求しない（ゲーム的単純化、意図的）。

> **【矛盾解消・確定】最小コア格変化セットの前倒し**：旧版は格変化パラダイム整備を M5（INC-5）監修に一括計上していたが、**格一致はコア体験（INC-1）なので、最小セットは INC-0/1 までに用意しないとコア検証が成立しない**（矛盾を解消）。分離方針は以下。
>
> - **INC-0/1 必須（最小コア格変化）**: 主格・対格の2格のみ、対象として実際に使う語に限定 = `fjandi/fjanda`、`sjálfr/sjalfan`、四大元素の主格/対格（暫定: `eldr/eld`・`vatn/vatn`・`vindr/vind`・`jörð/jörð`。中性/女性は同形あり）。これらは暫定値・`verified=false` でよいが**存在は必須**。
> - **INC-5（言語監修）に後置**: 与格・属格を含む全パラダイム、全語の精緻な語形確定、`verified=true` 化、出典確定。
>
> 実装エージェントは INC-1 着手時、最小コア格変化が `05` の `WordResource.inflection` に入っていることを前提にしてよい（無ければ先に最小セットを作る。全監修を待たない）。

## 4. 評価パイプライン（v0.2 から不変）

```
入力源（2系統 → 同一トークン列に正規化）
  ・通常モード: 習得語タイル列 ＋ 各対象語の指定格（格サブ選択）
  ・無辞書モード: 生テキスト（語形＝格変化の綴りまでプレイヤーが入力）
  │
  ▼  ① Tokenizer   語を Token 化（クラス・基本形・指定格/推定格）
  ▼  ② Parser       SpellAST を構築（3.1 の文法）
  ▼  ③ Validator    一致規則を検査 → GrammarReport（v0.18 で range_*/direction_* を追加）
  ▼  ④ Evaluator     AST から EffectSpec を生成（威力=Σ tier。属性合成解決）
  ▼  ⑤ SpatialResolver (v0.18 新規)  範囲語・方向語・タイル指定から対象タイル集合 T を計算
                                     視界外/壁/射程外で T が空なら「届かない」finding を追加
  ▼  ⑥ Resolver      制御精度でばらつき/暴発を解決 → ResolvedEffect
  ▼
戦闘へ適用（コマンド入力型ターン制 ＋ シームレス位置あり：1詠唱＝1プレイヤーターン＋世界時間Δ。`01` 3.8、`09` §6/§7）
```

**入力モデル（確定）**: トークナイザは「タイル列(語ID＋指定格)」と「生テキスト」の両入力を受け、内部表現を**同一トークン列に正規化**する。
- 通常モード: タイルは語幹/見出し語を選び、対象語タイルは**格サブ選択**（主格/対格/…）を持つ。選択式でも格は誤れる＝格一致が学習対象として成立する。
- 無辞書モード: 語形（格変化を含む綴り）まで入力。最高難度・暗記の実証。
- いずれも以降 ①〜⑤ は共通。テストは正規化後トークン列で行う。

M1（INC-1）では ①〜⑤ を戦闘なしのデバッグシーンで可視化。ruleset 注入で §6 のフェーズ解禁を実現。戦闘文脈は `01` 3.8 を正とする。

## 5. 数式モデル（制御精度・v0.3 改訂）

> 数値は初期値。INC-1/INC-5 で調整。**式の形**を仕様として固定し、係数はデータ化（`05` BalanceConfig）。

### 5.1 威力と制御の基礎量
- `P_base` = Σ(構成語の `tier` 重み)。**理解度に依存しない（成功時の威力天井）。**
- `C` = 呪文の理解度入力 = **使用した内容語の理解度の加重平均** ∈ [0,100]（正典定義。weakest-link 方式＝最小値採用は INC-1 で要否を要検証する tunable）。
- `G` = 文法スコア ∈ [0,1]（GrammarReport の pass 比率＋語順ボーナス補正）。

### 5.2 暴発確率（理解度＋文法の合算・v0.11 改訂）

**基準確率（v0.7 から不変）**:
```
base = clamp( 0.10 - 0.001 * C , 0 , 0.10 )
```
- 基準 10%（C=0）。理解度が 1 上がるごとに 0.1 ポイント（0.001）減少。
- `C=100 → base = 0`（**理解度100は暴発なし**。確定要件・後述合算後も維持）。

**文法違反による上乗せ倍率（v0.11 で追加）**:

| 違反種別（GrammarReport.rule） | 倍率 | 発生経路 | 備考 |
|--------------------------------|------|----------|------|
| `case_agreement` | ×2 | タイル経路／無辞書経路の両方 | 格不一致（コア違反、§3.3） |
| `unknown_word` | ×4 | 無辞書経路のみ | 綴り誤り＝辞書未マッチ（タイル経路では発生しない） |
| `word_order` | ×6 | タイル経路／無辞書経路の両方 | 正準語順から逸脱（§3.2） |

**合算式**:
```
if 違反 finding が 1 つもない:
    p_misfire = base
else:
    p_misfire = clamp( Σ_{i: 違反 finding} ( mult_i * base ) , 0 , 1 )
```

**計算例（C=50, base=0.05）**:
- 違反なし: `p = 0.05` (5%)
- 格違反のみ: `p = 2 × 0.05 = 0.10` (10%)
- 語順違反のみ: `p = 6 × 0.05 = 0.30` (30%)
- 格＋語順: `p = (2+6) × 0.05 = 0.40` (40%)
- 格＋スペル＋語順: `p = (2+4+6) × 0.05 = 0.60` (60%)

**C=100 では base=0 のため、上の例はすべて 0%**（達人は文法を間違えても暴発しない＝知識による完全制御。`01` の哲学保持）。

倍率テーブルは `05 BalanceConfig.misfire.mult_by_rule` への外出しを INC-2 で実施予定。INC-1 暫定では `core/spell/resolver.gd` にハードコード（`MISFIRE_MULT_BY_RULE` 定数）。

**責務分離（v0.11 でも維持）**:
- **暴発「が起きるか」（確率）** → 理解度＋文法（本式）
- **暴発「の重篤度カテゴリ」** → 理解度のみ（§5.3 バンド）
- **暴発「の被害量」** → 語ティア（§5.3 self_damage 等）
- **成功時の威力ぶれ・対象ズレ** → G スコア（§5.4 variance / target_jitter）
- **成功時の威力ボーナス** → 語順（§5.4 power_bonus）

> 設計判断（v0.6 → v0.7 → v0.11 の経緯）:
> - v0.6: `p=(0.50-0.005C)*grammar_penalty` で文法乗算込み。
> - v0.7: 「暴発＝理解度のみ、文法→命中精度のみ」へ責務分離。シンプル化。
> - v0.11: INC-1 spell_lab 実機検証で variance だけだと「格を直すと弱く外れる」体感が薄かった（実測: 正幅 0.32 vs 誤幅 0.47、平均威力はほぼ同等）。`06` §4.1.1「5分以内に自力で気づく」が苦しい。文法を確率に再合流させたが、v0.6 と違って (a) base × 倍率合算 で式を簡潔に、(b) `C=100 → base=0` の「達人不変条件」を温存、(c) 違反種別ごとに倍率を変えて「軽い間違いは軽く・致命的な間違いは重く」を表現。本作の哲学（理解度＝制御精度）は崩れていない（達人になれば文法は事実上ノーペナルティ＝練熟による完全制御の体感）。

### 5.3 暴発の内容＝理解度ティアで悪化（確定仕様）
暴発が起きた場合、その**結果の質は `C` のティアで決まる**。低理解度ほど安全な失敗、高理解度ほど危険な失敗（＝より精緻で強力なことに挑んで細部の制御を誤る）。

| ティア | `C` 範囲 | 失敗のカテゴリ | 代表的な結果（カタログ＝§5.3表） |
|--------|----------|----------------|----------------------------------|
| 低 | 0–30 | **発動の失敗** | 不発（効果ゼロ）／詠唱崩壊（効果消失、軽い体勢崩しのみ・無ダメージ）。最も安全な失敗 |
| 中 | 31–60 | **実行の失敗** | 対象ずれ（別対象/無方向へ）／威力低減（30–70%）／効果半減・範囲ズレ |
| 高 | 61–99 | **制御の失敗** | 手元で暴発＝自身へダメージ（意図威力の一部が自分へ）／効果反転（治癒→自傷、強化→自弱体）／反動 |
| 無 | 100 | 暴発しない（5.2 より p=0） | — |

> 設計意図: 「初心者の失敗は不発（痛くない）／達人の失敗は自爆（痛いが滅多に起きない）」。理解度を上げるほど失敗は減るが、残った失敗はより危険になる——この非対称性が緊張を生む。

暴発カタログの各結果の発生重みは `05` BalanceConfig（`misfire.catalog`）に外出し。`Resolver` は (1) `p_misfire` で暴発判定 → (2) 暴発なら `C` ティアでカタログ抽選 → (3) `EffectSpec` を当該失敗へ再解釈、の順。原因（理解度ティア＋文法違反）を `GrammarReport`/結果に必ず添える（§7）。

### 5.4 成功時の威力式（v0.12 改訂・G 線形乗算を追加）
暴発しなかった場合は基本的に成功。威力は **文法スコア G × 制御精度のぶれ** で決まる。
```
Control       = clamp01( 0.6*(C/100) + 0.4*G )
variance      = (1 - Control) * V_max(tier)         # 成功内のゆらぎ（小さめ）
g_mult        = G                                    # v0.12: 文法スコア線形乗算
effect_power  = P_base * g_mult * randNormal(mean=1.0, sd=variance)
target_jitter = (1 - Control) * J_max(tier)         # 成功内の微小ズレ
power_bonus   = 語順ボーナス（正準語順で +、§3.2）   # P_base に既に織り込み済（Evaluator）
```

**g_mult の意味（v0.12 で新規）**:
- G=1.0（文法 OK）→ g_mult=1.0 → 威力ペナルティなし
- G=0.5（コア違反 1 件）→ g_mult=0.5 → **威力半減**（文法 NG は決定的に弱い）
- G=0.0（コア違反全失敗）→ g_mult=0.0 → 威力ゼロ（成功しても効果なし、暴発と別経路の "失敗"）

**重要な不変条件**:
- **T1（P_base は C 不依存）は維持**: `P_base = Σtier + 語順ボーナス` は理解度に依らない。
- **達人不変条件は再定義**: C=100 でも g_mult は効くため、**達人は暴発しないが文法を間違えれば威力は半減する**。これにより v0.11 の「C=100 で文法違反のペナルティが消える」矛盾が解消される。
- 上振れで誤側が正側を超えることはなくなる（variance は g_mult 後の値に乗るため、誤側の最大値 ≈ P_base × G × (1 + variance_sd) < P_base 確定）。

> `variance`/`target_jitter` は「成功したが完璧ではない」表現用の小さな値。**categorical な失敗は 5.2/5.3 の暴発が担う**（二重ペナルティ回避のため V_max/J_max は控えめに設定）。g_mult は「文法的に弱い詠唱」の **確定的減衰** で、暴発・variance とは独立。三層構造（暴発：起きるか／variance：成功時のぶれ／g_mult：成功時の威力レベル）が役割分担。

> 設計判断（v0.12 記録）: v0.11 では暴発確率に文法を入れたが、C=100 では base=0 のため文法違反でも事実上ノーペナルティだった。実機検証で「達人になると誤の方がたまに威力が高くなる」現象が起きてメタ原則1（文法は罰ではなく情報）の "情報" が C=100 で空転していた。威力に G を線形乗算することで、文法は全 C 帯で意味を持つようになる。なお別案（G^0.5 等の緩衝）も検討したが、INC-1 の最重要シナリオ S1 の「**直すと明らかに良くなる**」体感のため、最も明瞭な線形を採用。INC-2 以降の戦闘で過剰と判断されたら BalanceConfig で緩衝関数に差し替える。

### 5.5 不変条件（テスト項目・v0.3 改訂）
- **T1（改訂）**: `P_base`（成功時の威力天井）は理解度に**不依存**。ただし *期待“到達”効果* は理解度とともに上がる（暴発＝特に低理解度の不発が減るため）。これは「知識＝制御」の意図された報酬。旧 v0.2 の「期待威力が理解度に完全不変」は本要件で**置換**（§0 と矛盾しない：威力ティアは依然理解度非依存、変わるのは“届く確率と安全性”）。
- **T2（v0.11 改訂）**: `base = clamp(0.10 - 0.001*C, 0, 0.10)`。`C` に対し単調減少、`C=0`で 0.10、`C=100`で 0。線形性と境界をテストで確認。文法違反ゼロのとき `p_misfire = base` であることもテスト。
- **T3（改訂）**: 暴発結果のカテゴリが `C` バンド境界（≤30 / 31–60 / 61–99 / =100）で「発動失敗→実行失敗→制御失敗→無」へ遷移することをテストで確認。**カテゴリ判定は理解度のみ依存（文法に不依存）。**
- **T4（改訂）**: 強ティア・低理解度の語は「成功すれば高威力だが C=0 で 10% 暴発し、暴発時は不発（軽傷）」。使い込み `C` が上がると暴発率は下がるが、残る暴発は実行失敗→自爆へと重篤化する。戦略的選択（強い未習語を博打で撃つ／安全な既習語で堅実に）が成立。
- **T5（v0.11 反転）**: `p_misfire` は **理解度と文法の合算**。違反 finding ごとに `base × mult` を加算（case=2/unknown_word=4/word_order=6）。
  - 違反ゼロ → `p_misfire = base`（T2 と一致）。
  - 違反複数 → 上乗せが加算合成される（例: C=50・格＋語順 → `p_misfire = 0.40`）。
  - `C=100` では `base=0` のため、文法違反があっても `p_misfire = 0`（達人不変条件・§5.2）。
  - **重篤度カテゴリは文法に不依存**（C のみ）。文法は確率にのみ作用、カテゴリと被害量は理解度／ティアの責務（§5.3）。
- **T9（v0.15 新規）**: word_order ルール が enabled の場合、effect → target VO 順序（既存）に加え以下を判定:
  - 修飾語が target に隣接していること（直前/直後）。離れていれば word_order finding。
  - 属性語は effect の前 or target の後にあること。effect-target の間に挟まれていれば word_order finding。
  - INC-1 では「形容詞は target の直前（前置修飾）」を推奨パターン、直後は許容、離れは NG。
  - 倍率は ×6（既存）。
- **T8（v0.14 新規）**: modifier ルールが enabled かつ修飾語が形容詞活用を持つ場合、target との性・数・格一致を判定する。
  - 修飾語の指定 case が target.case と異なる → modifier_agreement finding。
  - case 一致でも target.gender × case の活用形が辞書未定義なら警告 finding。
  - 暴発確率倍率は ×2.0（case_agreement と同等の重み）。
  - 形容詞活用を持たない修飾語（副詞等、`has_gendered_inflection() == false`）は判定対象外。
- **T7（v0.13 新規）**: elements / modifier ルールが ruleset で enabled な場合、Validator は最小判定を行う。
  - 四大元素の 2-3 個組み合わせは elements finding を出す（暴発 ×1.5）。4 個全部は混沌属性 OK。
  - 修飾語あり＋効果語なしは modifier finding を出す（暴発 ×1.5）。
  - phase_intro / phase_beginner では modifier disabled なので mikill を含めても modifier finding は出ない（可用性ゲート）。
  - Evaluator は modifier ありで mikill=×1.5, litill=×0.7 を P_base に乗算（複数あれば積）。
- **T6（v0.12 新規）**: 成功時の `effect_power = P_base × G × randNormal(1.0, variance)`。文法違反があれば G<1.0 となり、**C に関わらず**威力が確定的に減衰。
  - C=100, G=1.0 → 威力 = P_base 確定
  - C=100, G=0.5（格違反）→ 威力 = P_base × 0.5 ≈ 確定（variance も微小）
  - C=50, G=1.0 → 威力 ≈ P_base ± 6%
  - C=50, G=0.5 → 威力 ≈ P_base × 0.5 ± 10%（さらに 10% で暴発）
  - 「達人は暴発しないが文法を間違えれば威力は半減する」が新しい不変条件。
- **T10（v0.18 新規・INC-3.5 で本格化）**: 範囲語の射程外検出が機能する。
  - `nær meiða fjanda` で対象がマンハッタン距離 3 → range_required finding、対象タイル集合 T が空 → ダメージ 0。
  - `nær fjarri meiða fjanda` → range_conflict finding（暴発 ×3、INC-3.5）。
  - `vítt meiða fjanda` で方向語もタイル指定も無い → direction_required finding、詠唱不可（scaffold=max は事前ブロック）。
  - `í gegnum fram meiða fjanda` で壁を貫通し線上の全敵が対象 T に入る（`09 §7.1`）。
- **T11（v0.18 新規・INC-3.5 で本格化）**: 方向語はプレイヤーの向きを基準とした相対方向で対象タイルを決定する。
  - プレイヤーが北向き・`fram meiða fjanda` → +Y'(-y) 方向の最隣接敵が対象。
  - プレイヤーが東向き・`vinstri meiða fjanda` → -y 方向（北）の最隣接敵が対象。
  - 旋回（Δ 0）で向きを変えると同じ呪文でも対象が変わる（`09 §3.2/§7.2`）。
  - INC-3 では minor finding のみ、INC-3.5 で本表通りコア違反扱い・対象タイル T 計算を Validator/SpatialResolver で検証。

## 6. 文法習熟モデル（D1〜D8 確定）

**確定原則（項目5の決定）**
- **D1/D8: 文法習熟は数値ステータスを持たない。** その場の正誤 `G`（§5.4 で命中精度に作用）＋フェーズ解禁状態のみ。文法に永続的な威力/確率ステータスは無い。真の文法知識はプレイヤー自身に置く（メタ原則）。
- **D3: 判定の厳しさは常時一定。** コア規則（**格一致・語順**）は最初から常時厳格に判定される（寛容フェーズは無い）。フェーズで変わるのは「UI 補助の量」と「使用可能な構文（可用性）」のみ。
- **D4: データは規則単位（`05` GrammarRuleset）。プレイヤー提示は4フェーズの束。** `enabled` は「寛容に無視する/しない」ではなく「**その構文が導入済み＝使用可能か**」を意味する（可用性ゲートであって寛容化ではない）。
- **D2: フェーズ解禁の引き金＝物語進行が主、習熟実証が従。** 師匠の遺した知識を辿る進行で構文と補助段階が進む。直前帯の規則で正しい詠唱を重ねると解禁を前倒しできる（従）。
- **D7: 解禁・補助段階は巻き戻しで戻らない。** 知識側として SaveData に恒久記録（語彙理解度と同じ）。引き金イベントがループ内で起きても解禁自体は恒久（タイムループの定石）。
- **D6: 語彙理解度は「文法的に正しい詠唱」でのみ伸びる。** 誤った詠唱は獲得なし＋是正フィードバック（§7）。

### 6.1 補助段階（scaffold level・物語で逓減）
| 段階 | 補助レベル | 補助内容（コア規則は常時厳格判定。これは"手取り足取りの量"） | INC-1 実装 (v0.16) |
|------|-----------|--------------------------------------------------------------|---|
| 入門 max | 最大 | 正しい格を自動提示/補完、不正語順をグレーアウト、ライブ文法プレビュー | ✅ ライブプレビュー + 修飾語自動配置 + 格デフォルト |
| 初級 mid | 中 | ヒントは要求時のみ（ホバー/ボタン）、詠唱前に警告ダイアログ | ✅ ヒントボタン + 詠唱前 ConfirmationDialog |
| 中級 low | 小 | 詠唱後の `GrammarReport` 是正フィードバックのみ（これは全段階で常時あり） | ✅ 既存挙動 |
| 上級 none | なし | 補助一切なし | ✅ GrammarReport を簡略化（詳細非表示） |
| 無辞書（碑文）モード | なし＋ | 上級の補助ゼロに加え、語彙タイルも隠し**全タイプ入力**＋使用可能範囲で**最厳 ruleset 強制** | ⏳ INC-2/3（freetext tokenizer + unknown_word ×4） |

> 補助はあくまで入力支援。**格一致・語順の合否そのものは段階に依らず一定**（誤れば §5.4 で弱く外れ、`GrammarReport` が原因提示）。これが「補助型(D3)」の意味。

### 6.2 構文の可用性ゲート（抽出語彙を割付、v0.18 改訂）
解禁されるまで当該構文・語はプレイヤーに登場しない（寛容化ではなく未登場）。

| 学習段階 | 解禁構文（可用性） | コア語彙（抽出） | 区分 |

> **v0.18 改訂理由**: マス目移動・シームレス戦闘の導入により、方向語・範囲語は「無いと対象指定ができない」コア機能になった（`09 §6/§7`）。よって入門段階から `fram`/`aptr` を解禁し、初級で 4 方向を揃え、中級で AoE/貫通という形状語を出す段階的解禁とする。修飾語 `mikill`/`lítill` は v0.14 で性数格一致まで含めてコアに格上げ済みだが、可用性は中級から（複雑度のため）。
>
> **INC-3 暫定**: ruleset 上は本表のとおり解禁するが、Validator のコア違反扱いは INC-3.5 から（INC-3 は minor finding にとどめる、`09 §8`）。これにより INC-3 中の認知負荷を抑え、INC-3.5 で本格適用する段階移行を可能にする。

> **コア確定（v0.18 追記）:** コアの面白さ判定の到達点は段階によって異なる。
> - **INC-1/2**: **入門＋初級（格一致を補助減で体得）まで**で成立。格一致判定は INC-1 から常時有効。中級以降は可用性で後出し。
> - **INC-3**: 入門＋初級＋初級+（属性語・遠距離）まで。範囲語・方向語は ruleset 解禁済みだが Validator は minor finding にとどめる（コア違反扱いしない）。
> - **INC-3.5**: 入門〜中級まで。範囲語・方向語をコア違反扱いに格上げし、H/H2 を新仕様で再判定（`06`/`08` 再確認章）。
>
> 実装: `Validator` は使用可能な構文集合（解禁状態）を ruleset として受け取る。**未解禁構文は入力に出さない**＝寛容判定はしない。コア規則は常に厳格。補助段階は UI 層（`04` SpellComposer）が担い、`Validator` の合否には影響しない。INC-3 / INC-3.5 の minor → コア違反の格上げは `BalanceConfig.misfire.mult_by_rule.range_*/direction_*` のスイッチで切替可能にする（`09 §10`）。

## 7. フィードバック設計（v0.3 改訂）

暴発・誤射時、UI は必ず提示する:
1. **何が起きたか**（§5.3 ティア由来：不発／対象ズレ・威力低減／自爆・反転 のいずれか）。
2. **なぜか**（2系統を併記）
   - 理解度由来: 「この呪文の理解度は低/中（C≈xx）。理解度を上げると暴発が減ります」（§5.2 の確率と §5.3 のティアを噛み砕く）。
   - 文法由来: GrammarReport の最重要違反 1〜2 件（例:「対格ではありません: `fjandi` → `fjanda`?」）。
3. **どう直すか**（推奨修正＋「使い込む/集中学習で理解度を上げる」導線）。

> 重要: 理解度が高いのに自爆系（§5.3 高ティア）で失敗したケースでは、「理解はあるが制御を誤った＝あと一歩」というニュアンスを出し、低理解度の不発（基礎不足）と**メッセージを区別**する。失敗の質がそのまま学習の手がかりになる（教育設計＝ゲーム設計の一体化）。

> 文言の日英対訳テンプレは **附録B** を参照（`gloss` 同様ロケール別。JA先行・ENリリース必須＝`05`/`01` 6.1）。

## 8. 実装上の注意

- 発音表記（`reading_kana`/`ipa`、`05`）は**表示・教育用のみ**。トークナイザ/パーサ/Validator/Resolver は一切参照しない（DP2）。正典トークンは古綴ラテン表記（附録A 表記ポリシー）。無辞書モードはグロス・カナとも非表示（DP3）。グロスはロケール別（`05` `gloss[locale]`、JA先行・ENリリース必須）。

- 語形変化表は**データ駆動**（`05` の `WordResource.inflection`）。語形をコードにハードコードしない。
- 抽出語彙は附録Aの出典・信頼度を `WordResource.source` / `verified` に転記。信頼度 ✅ は `verified=true` 候補、◎⚠❓ は M5 監修対象。
- パーサは規則を**注入可能 ruleset** として設計（§6）。ruleset は「使用可能な構文集合（解禁状態）」を表す。**未解禁構文は入力に出さない＝寛容判定しない。コア規則（格一致・語順）の合否は段階に依らず常に厳格。**
- **補助段階（§6.1）は UI 層（`04` SpellComposer）の責務で、`Validator` の合否・`G` には一切影響しない。** 文法は数値ステータスを持たない（D1）。`Validator` をテストする際、補助段階の状態を入力に含めないこと（疎結合）。
- 乱数は seed 管理（リプレイ・デバッグ・ローグライク再現性）。
- 旧辞典の MP/ターン値は**移植しない**（§0.2）。威力は `tier`、時間コストは `02`/`05` 側の世界時間モデルで扱う。
- **【最重要・移植禁止】旧辞典の効果語ダメージ式（`理解度値 × …`／`÷ 敵耐性値`／`− 敵防御値`）をそのまま実装しないこと。** 本作では理解度は**成功時の威力（`P_base`）には一切寄与しない**（威力ティアは理解度非依存：§1-1、§5.1、T1）。理解度が変えるのは「暴発の確率と質」だけ（§5.2/5.3）。結果として“敵に届く期待効果”は理解度とともに上がるが、それは**威力式に理解度を掛けるからではなく不発が減るから**——この区別を実装で守る。辞典の効果欄は「何が起きるか（害/治癒/弱体/移動）」の意味だけを抽出し、量的計算は §5 で再構築する。誤ると本作のテーマ（理解度＝制御／知識は残るが力は残らない）が崩壊する。
