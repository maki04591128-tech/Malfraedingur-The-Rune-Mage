## 0. 旧辞典からの抽出方針（流用境界）

本書 v0.3 は別プロジェクトの辞典を参照元とする。**そのまま使わず、本作の設計に整合する部分のみ抽出**した。境界を明示する。

### 0.1 流用したもの（抽出・採用）
- **検証済み語彙**：原型・語源・品詞（語形変化型付き）・意味・カナ読み。さらに **CV / Zoëga / Wiktionary / ONP / Skaldic による文献裏取りと信頼度（✅◎⚠❓）**。→ 本作の「要 M5 言語監修」リスクを大幅低減（出典付きで採用可能）。
- **語クラス分類体系**：効果語／対象語／属性語／修飾語／範囲語／条件語／数値語／時間単位語／条件詳細語（／末尾語）。旧 v0.2 の簡易分類より精緻なため置換採用。
- **システム概念**：四大元素の合成（4 元素全部入りで「混沌属性」化）、修飾語の威力スケール、範囲語、`ef` ＋条件詳細語による条件詠唱の構造。

### 0.2 流用しなかったもの（非採用・理由）
| 旧辞典の要素 | 非採用理由 | 本作での代替 |
|--------------|------------|--------------|
| 基礎消費MP / 詠唱ターン | 本作は MP 制でなく **タイムリミット制**（理解度は威力でなく制御精度に作用、`01`） | 語の `tier`（固有威力）＋世界時間消費（`02`/`05`） |
| **効果語のダメージ式・敵耐性値・敵防御値**（例: `meiða`＝`現在Lv × 理解度値 ÷ 敵耐性値 − 敵防御値`） | **理解度を威力乗数に使う設計で、本作のコア原則「理解度＝制御精度であって威力ではない」と真逆。式ごと移植すると別ゲーム化する** | 威力は `P_base = Σ tier`（理解度非依存）。理解度・文法は §5 の制御精度（ばらつき/暴発）にのみ作用。属性相剋は威力期待値でなく有利/不利の方向性として表現（附録A.3） |
| フリー版／有料版の区分 | 本作にその区分は無い | 削除 |
| Ver.1.0 / Ver.1.1 等の版管理 | 旧プロジェクトのリリース計画 | 本作の **学習段階フェーズ**（§6）に再マップ |
| クエスト専用語・演出専用語（`loka`/`Helgrind`/`öld`/`renna`） | 旧作の物語に密結合のため**コア戦闘文法には載せない** | v0.4で枠物語確定により**物語固定詠唱／固有名詞として採用**：`öld renna aptr`＝巻き戻し、`Helgrind`＝ダンジョン名（附録A.9）。コア呪文エンジンとは独立した固定イベント扱い |
| 習得地域（Vitruhæðir 等の固有地名） | 旧作のマップに密結合 | 抽象的な「習得契機（碑文/ドロップ/学習）」に再マップ（`01`） |
| 組合せ算術表（11,657 通り等） | 旧作の版別バケット集計 | 非採用。設計指標としての「組合せ規模」概念のみ参考 |
| ルートA/B/C・クライマックス呪文 | 旧作の物語構造 | 非採用 |

## 1. 設計原則（v0.2 から不変）

1. **威力は語の固有ティアで決まる。理解度は威力に影響しない。**
2. **理解度と文法的正しさは「制御精度」（ばらつき・暴発）に影響する。**
3. 文法は「罰」ではなく「情報」。失敗時はプレイヤーが**原因を特定できる**フィードバックを返す。
4. 文法スコープは学習設計（`01` 4章）と一対一対応。実装も学習段階順に解禁。
5. **語彙は出典付きで採用する。** 各語に文献裏取りと信頼度を持たせ `verified` を管理（`05`）。

## 2. 語クラス分類（旧辞典準拠に拡張）

| クラス | 役割 | 本作での文法上の扱い |
|--------|------|----------------------|
| 効果語（動詞 sögn） | 呪文の作用本体（害す/守る/癒す/弱める…） | 他動詞は目的語の**格**を要求（コアの格一致対象） |
| 対象語（名詞/代名詞） | 詠唱対象の指定（敵/自己） | 効果語の目的語。格を担う |
| 属性語（元素名詞） | 効果に属性を付与（火/水/風/土/光/闇） | 4 元素全部入り＝**混沌属性**化（特殊合成） |
| 修飾語（形容詞副詞用法） | 威力スケール（大/小） | 威力に乗算。語形は被修飾と一致が望ましい |
| 範囲語 | 効果範囲拡張（近傍/広域） | 【ストレッチ】効果範囲を変える |
| 条件語 `ef` | 条件詠唱の導入 | 【ストレッチ】条件節を構成 |
| 条件詳細語 | 条件の中身（負傷/耐性/弱点…） | 【ストレッチ】`ef` と組む |
| 数値語 | 量（1/3/5/7…） | 【ストレッチ】持続/範囲の数量 |
| 時間単位語 | 持続単位（ひととき/時） | 【ストレッチ】数値語と結合し持続化 |
| 末尾語（方向） | 移動方向（前後左右） | 【ストレッチ・任意】移動効果語と結合する独立枝 |

各語は理解度 `comprehension ∈ [0,100]` と固有ティア `tier ∈ {1,2,3}` を持つ（スキーマ `05`）。
**コア検証（M1〜M3）で扱うのは「効果語＋対象語＋格一致」と、補助的に属性語まで。** それ以外は §6 のとおりストレッチ。

## 3. 呪文構文（文法）

### 3.1 基本文型（EBNF 風）

```
spell        := [number time_unit] [condition] [range] [modifier] [element] verb object
condition    := "ef" cond_clause
cond_clause  := target cond_detail              # 例: sjálfr sárr（自身が負傷）
element      := element_word { element_word }    # 4元素全部で混沌属性
modifier     := "mikill" | "lítill"
range        := "nær" | "vítt"
object       := target_word
verb         := effect_word
```

**v0.3 スコープ注記:**
- **コア（M1〜M3 で実装）**: `verb object` ＋ **格一致**。補助で `element verb object`（属性付与）まで。
- **【ストレッチ】（M4以降）**: `number time_unit` / `condition`(`ef`+条件詳細) / `range` / `modifier` / 末尾語方向。エンジンは将来これらを足せる構造（`04` の注入可能 ruleset）で作るが、コア検証時は ruleset で**無効化**して出さない。

コア検証で実際に扱う最小例（抽出語彙ベース）:
```
meiða fjanda           # 害す＋敵(対格)  → 格一致 → 命中
meiða fjandi           # 害す＋敵(主格)  → 格不一致 → 誤射（コア体験の核）
eldr meiða fjanda      # 火属性で敵を害す（属性語の補助スコープ）
lækna sjalfan          # 自らを癒す（対格・再帰）
```

ストレッチ到達形（旧辞典の条件詠唱を本作流に再構成。**コア検証では使わない**）:
```
ef sjálfr sárr  lækna sjálfr
（もし自らが負傷していたら、自らを癒せ）
```

### 3.2 正準語順（Canonical Order）
`[数値 時間単位] [ef 条件] [範囲] [修飾] [属性] 効果語 対象語`

- 正準語順 → **語順ボーナス**（制御精度 +、ばらつき −）。
- 語順崩れ → ボーナス消失。重度崩れ → 暴発確率上昇。
- 古ノルド語は語順が比較的自由だが、本作はゲーム的単純化として「正準形に近いほど安定」と定義（意図的単純化。`01` 非目標）。

### 3.3 文法一致規則（実装すべき判定）

| 規則 | 内容 | 違反時の既定挙動 | 区分 |
|------|------|------------------|------|
| 格一致 (case) | 他動詞の目的語は対格。`meiða fjanda`◯ / `meiða fjandi`✕ | 対象がブレる（誤射） | **コア** |
| 属性合成 | 元素語の組合せ規則（4元素全部＝混沌属性） | 半端な組合せは属性不発 | コア補助 |
| 修飾一致 | 修飾語は被修飾と性・数・格一致が望ましい | 修飾効果が減衰/不発 | 【ストレッチ】 |
| 数一致 | 数値語と名詞/時間単位語の一致 | 持続/範囲値が乱れる | 【ストレッチ】 |
| 条件節構造 | `ef` の後に評価可能な条件詳細語 | 条件無視で無条件発動（危険） | 【ストレッチ】 |

→ 判定結果は **`GrammarReport`**（規則ごと pass/fail と理由）。UI が人間可読フィードバックに変換（§7）。

> **本作の格運用ルール（重要）**：旧辞典は「数値語は格一致を要求しない」等の DSL 簡略を採っていた。本作は**コア体験が格一致なので、対象語については格一致を必須化**する。`fjandi`(主格)/`fjanda`(対格)、`sjálfr`(主格)/`sjalfan`(対格・再帰) のように対象語は格変化表をデータで持つ（`05` の `WordResource.inflection`）。属性語・数値語・末尾語は格一致を要求しない（ゲーム的単純化、意図的）。

> **【矛盾解消・確定】最小コア格変化セットの前倒し**：旧版は格変化パラダイム整備を M5（INC-5）監修に一括計上していたが、**格一致はコア体験（INC-1）なので、最小セットは INC-0/1 までに用意しないとコア検証が成立しない**（矛盾を解消）。分離方針は以下。
>
> - **INC-0/1 必須（最小コア格変化）**: 主格・対格の2格のみ、対象として実際に使う語に限定 = `fjandi/fjanda`、`sjálfr/sjalfan`、四大元素の主格/対格（暫定: `eldr/eld`・`vatn/vatn`・`vindr/vind`・`jörð/jörð`。中性/女性は同形あり）。これらは暫定値・`verified=false` でよいが**存在は必須**。
> - **INC-5（言語監修）に後置**: 与格・属格を含む全パラダイム、全語の精緻な語形確定、`verified=true` 化、出典確定。
>
> 実装エージェントは INC-1 着手時、最小コア格変化が `05` の `WordResource.inflection` に入っていることを前提にしてよい（無ければ先に最小セットを作る。全監修を待たない）。

## 4. 評価パイプライン（v0.2 から不変）

```
入力源（2系統 → 同一トークン列に正規化）
  ・通常モード: 習得語タイル列 ＋ 各対象語の指定格（格サブ選択）
  ・無辞書モード: 生テキスト（語形＝格変化の綴りまでプレイヤーが入力）
  │
  ▼  ① Tokenizer   語を Token 化（クラス・基本形・指定格/推定格）
  ▼  ② Parser       SpellAST を構築（3.1 の文法）
  ▼  ③ Validator    一致規則を検査 → GrammarReport
  ▼  ④ Evaluator     AST から EffectSpec を生成（威力=Σ tier。属性合成解決）
  ▼  ⑤ Resolver      制御精度でばらつき/暴発を解決 → ResolvedEffect
  ▼
戦闘へ適用（コマンド入力型ターン制：1詠唱＝1プレイヤーターン＋世界時間Δ。`01` 3.8）
```

**入力モデル（確定）**: トークナイザは「タイル列(語ID＋指定格)」と「生テキスト」の両入力を受け、内部表現を**同一トークン列に正規化**する。
- 通常モード: タイルは語幹/見出し語を選び、対象語タイルは**格サブ選択**（主格/対格/…）を持つ。選択式でも格は誤れる＝格一致が学習対象として成立する。
- 無辞書モード: 語形（格変化を含む綴り）まで入力。最高難度・暗記の実証。
- いずれも以降 ①〜⑤ は共通。テストは正規化後トークン列で行う。

M1（INC-1）では ①〜⑤ を戦闘なしのデバッグシーンで可視化。ruleset 注入で §6 のフェーズ解禁を実現。戦闘文脈は `01` 3.8 を正とする。

## 5. 数式モデル（制御精度・v0.3 改訂）

> 数値は初期値。INC-1/INC-5 で調整。**式の形**を仕様として固定し、係数はデータ化（`05` BalanceConfig）。

### 5.1 威力と制御の基礎量
- `P_base` = Σ(構成語の `tier` 重み)。**理解度に依存しない（成功時の威力天井）。**
- `C` = 呪文の理解度入力 = **使用した内容語の理解度の加重平均** ∈ [0,100]（正典定義。weakest-link 方式＝最小値採用は INC-1 で要否を要検証する tunable）。
- `G` = 文法スコア ∈ [0,1]（GrammarReport の pass 比率＋語順ボーナス補正）。

### 5.2 暴発確率（理解度のみ・線形・確定仕様）
```
p_misfire = clamp( 0.10 - 0.001 * C , 0 , 0.10 )
```
- **基準 10%（C=0）。理解度が 1 上がるごとに 0.1 ポイント（0.001）減少。**
- `C=100 → p_misfire = 0`（**理解度100は暴発なし**。確定要件）。
- 単調性: `C` 増加で `p_misfire` は単調減少（C=0で最大 0.10、C=50で 0.05、C=100で 0）。
- **暴発確率は理解度のみで決まる（確定）。** 文法の正しさ・語ティア・語順は暴発「確率」には影響しない。これらの責務は次のとおり分離（ユーザー指定モデルに合わせた整理）:
  - **文法（G）** → 成功時の威力ぶれ・対象ズレ（§5.4 の `variance`/`target_jitter`）と**学習フィードバック**（§7）。「格を間違えると弱く・外れ、原因が提示される」というコア体験はここで担保（暴発確率ではなく命中精度で表現）。
  - **語ティア** → 暴発が起きた際の**被害の大きさ**（§5.3：tier が高いほど自爆ダメージ等が比例して痛い）。確率ではなく結果の重さに効く。
  - **語順ボーナス** → 成功時の威力ボーナス（§5.4 `power_bonus`）。

> 設計判断（記録）: 旧 v0.6 は `p=(0.50-0.005C)*grammar_penalty` の文法乗算込みだった。ユーザー確定仕様により**暴発確率を理解度線形 10%/−0.1pt の単純式へ置換し、文法は確率から切り離した**。文法学習の動機は「弱く外れる＋明確な是正フィードバック」と威力ボーナスで全帯に残る。再び文法を暴発確率に絡めたい場合は本式に加法ペナルティを足す拡張余地あり（未採用・要相談）。

### 5.3 暴発の内容＝理解度ティアで悪化（確定仕様）
暴発が起きた場合、その**結果の質は `C` のティアで決まる**。低理解度ほど安全な失敗、高理解度ほど危険な失敗（＝より精緻で強力なことに挑んで細部の制御を誤る）。

| ティア | `C` 範囲 | 失敗のカテゴリ | 代表的な結果（カタログ＝§5.3表） |
|--------|----------|----------------|----------------------------------|
| 低 | 0–30 | **発動の失敗** | 不発（効果ゼロ）／詠唱崩壊（効果消失、軽い体勢崩しのみ・無ダメージ）。最も安全な失敗 |
| 中 | 31–60 | **実行の失敗** | 対象ずれ（別対象/無方向へ）／威力低減（30–70%）／効果半減・範囲ズレ |
| 高 | 61–99 | **制御の失敗** | 手元で暴発＝自身へダメージ（意図威力の一部が自分へ）／効果反転（治癒→自傷、強化→自弱体）／反動 |
| 無 | 100 | 暴発しない（5.2 より p=0） | — |

> 設計意図: 「初心者の失敗は不発（痛くない）／達人の失敗は自爆（痛いが滅多に起きない）」。理解度を上げるほど失敗は減るが、残った失敗はより危険になる——この非対称性が緊張を生む。

暴発カタログの各結果の発生重みは `05` BalanceConfig（`misfire.catalog`）に外出し。`Resolver` は (1) `p_misfire` で暴発判定 → (2) 暴発なら `C` ティアでカタログ抽選 → (3) `EffectSpec` を当該失敗へ再解釈、の順。原因（理解度ティア＋文法違反）を `GrammarReport`/結果に必ず添える（§7）。

### 5.4 成功時の残ぶれ（軽微）と語順ボーナス
暴発しなかった場合は基本的に成功。ただし制御精度に応じた**軽微なぶれ**を残す（破綻ではない精度のゆらぎ）。
```
Control       = clamp01( 0.6*(C/100) + 0.4*G )
variance      = (1 - Control) * V_max(tier)         # 小さめ。成功内のゆらぎ
effect_power  = P_base * randNormal(mean=1.0, sd=variance)
target_jitter = (1 - Control) * J_max(tier)         # 成功内の微小ズレ
power_bonus   = 語順ボーナス（正準語順で +、§3.2）   # 文法を正しく保つ動機（C=100でも有効）
```
> `variance`/`target_jitter` は「成功したが完璧ではない」表現用の小さな値。**categorical な失敗は 5.2/5.3 の暴発が担う**（二重ペナルティ回避のため V_max/J_max は控えめに設定）。

### 5.5 不変条件（テスト項目・v0.3 改訂）
- **T1（改訂）**: `P_base`（成功時の威力天井）は理解度に**不依存**。ただし *期待“到達”効果* は理解度とともに上がる（暴発＝特に低理解度の不発が減るため）。これは「知識＝制御」の意図された報酬。旧 v0.2 の「期待威力が理解度に完全不変」は本要件で**置換**（§0 と矛盾しない：威力ティアは依然理解度非依存、変わるのは“届く確率と安全性”）。
- **T2（改訂）**: `p_misfire = clamp(0.10 - 0.001*C, 0, 0.10)`。`C` に対し単調減少、`C=0`で 0.10、`C=100`で 0。線形性と境界をテストで確認。
- **T3（改訂）**: 暴発結果のカテゴリが `C` バンド境界（≤30 / 31–60 / 61–99 / =100）で「発動失敗→実行失敗→制御失敗→無」へ遷移することをテストで確認。
- **T4（改訂）**: 強ティア・低理解度の語は「成功すれば高威力だが C=0 で 10% 暴発し、暴発時は不発（軽傷）」。使い込み `C` が上がると暴発率は下がるが、残る暴発は実行失敗→自爆へと重篤化する。戦略的選択（強い未習語を博打で撃つ／安全な既習語で堅実に）が成立。
- **T5（改訂）**: `p_misfire` は **文法・語ティア・語順に不依存**（理解度のみの関数）。一方 `variance`/`target_jitter`/`power_bonus` は文法（G）・語順で変動し、`GrammarReport` に是正情報が出る——文法学習の動機が全帯で残ることをテストで確認。

## 6. 文法習熟モデル（D1〜D8 確定）

**確定原則（項目5の決定）**
- **D1/D8: 文法習熟は数値ステータスを持たない。** その場の正誤 `G`（§5.4 で命中精度に作用）＋フェーズ解禁状態のみ。文法に永続的な威力/確率ステータスは無い。真の文法知識はプレイヤー自身に置く（メタ原則）。
- **D3: 判定の厳しさは常時一定。** コア規則（**格一致・語順**）は最初から常時厳格に判定される（寛容フェーズは無い）。フェーズで変わるのは「UI 補助の量」と「使用可能な構文（可用性）」のみ。
- **D4: データは規則単位（`05` GrammarRuleset）。プレイヤー提示は4フェーズの束。** `enabled` は「寛容に無視する/しない」ではなく「**その構文が導入済み＝使用可能か**」を意味する（可用性ゲートであって寛容化ではない）。
- **D2: フェーズ解禁の引き金＝物語進行が主、習熟実証が従。** 師匠の遺した知識を辿る進行で構文と補助段階が進む。直前帯の規則で正しい詠唱を重ねると解禁を前倒しできる（従）。
- **D7: 解禁・補助段階は巻き戻しで戻らない。** 知識側として SaveData に恒久記録（語彙理解度と同じ）。引き金イベントがループ内で起きても解禁自体は恒久（タイムループの定石）。
- **D6: 語彙理解度は「文法的に正しい詠唱」でのみ伸びる。** 誤った詠唱は獲得なし＋是正フィードバック（§7）。

### 6.1 補助段階（scaffold level・物語で逓減）
| 段階 | 補助レベル | 補助内容（コア規則は常時厳格判定。これは"手取り足取りの量"） |
|------|-----------|--------------------------------------------------------------|
| 入門 | 最大 | 正しい格を自動提示/補完、不正語順をグレーアウト、ライブ文法プレビュー |
| 初級 | 中 | ヒントは要求時のみ（ホバー/ボタン）、詠唱前に警告ダイアログ |
| 中級 | 小 | 詠唱後の `GrammarReport` 是正フィードバックのみ（これは全段階で常時あり） |
| 上級 | なし | 補助一切なし |
| 無辞書（碑文）モード | なし＋ | 上級の補助ゼロに加え、語彙タイルも隠し**全タイプ入力**＋使用可能範囲で**最厳 ruleset 強制** |

> 補助はあくまで入力支援。**格一致・語順の合否そのものは段階に依らず一定**（誤れば §5.4 で弱く外れ、`GrammarReport` が原因提示）。これが「補助型(D3)」の意味。

### 6.2 構文の可用性ゲート（抽出語彙を割付）
解禁されるまで当該構文・語はプレイヤーに登場しない（寛容化ではなく未登場）。

| 学習段階 | 解禁構文（可用性） | コア語彙（抽出） | 区分 |
|----------|---------------------|------------------|------|
| 入門 | 効果語＋対象語（格一致は最初から厳格判定） | `meiða` `verja` `lækna` / `fjandi` `sjálfr` | **コア** |
| 初級 | 同上を補助減で熟達（格一致の体得） | 同上（対格 `fjanda`/`sjalfan`） | **コア（コア検証の到達点）** |
| 初級+ | 属性語の付与・混沌合成 | `eldr` `vatn` `vindr` `jörð`（＋`ljós` `myrkr`） | コア補助 |
| 中級 | 修飾語・範囲語 | `mikill` `lítill` / `nær` `vítt` | 【ストレッチ】 |

## 7. フィードバック設計（v0.3 改訂）

暴発・誤射時、UI は必ず提示する:
1. **何が起きたか**（§5.3 ティア由来：不発／対象ズレ・威力低減／自爆・反転 のいずれか）。
2. **なぜか**（2系統を併記）
   - 理解度由来: 「この呪文の理解度は低/中（C≈xx）。理解度を上げると暴発が減ります」（§5.2 の確率と §5.3 のティアを噛み砕く）。
   - 文法由来: GrammarReport の最重要違反 1〜2 件（例:「対格ではありません: `fjandi` → `fjanda`?」）。
3. **どう直すか**（推奨修正＋「使い込む/集中学習で理解度を上げる」導線）。

> 重要: 理解度が高いのに自爆系（§5.3 高ティア）で失敗したケースでは、「理解はあるが制御を誤った＝あと一歩」というニュアンスを出し、低理解度の不発（基礎不足）と**メッセージを区別**する。失敗の質がそのまま学習の手がかりになる（教育設計＝ゲーム設計の一体化）。

> 文言の日英対訳テンプレは **附録B** を参照（`gloss` 同様ロケール別。JA先行・ENリリース必須＝`05`/`01` 6.1）。

## 8. 実装上の注意

- 発音表記（`reading_kana`/`ipa`、`05`）は**表示・教育用のみ**。トークナイザ/パーサ/Validator/Resolver は一切参照しない（DP2）。正典トークンは古綴ラテン表記（附録A 表記ポリシー）。無辞書モードはグロス・カナとも非表示（DP3）。グロスはロケール別（`05` `gloss[locale]`、JA先行・ENリリース必須）。

- 語形変化表は**データ駆動**（`05` の `WordResource.inflection`）。語形をコードにハードコードしない。
- 抽出語彙は附録Aの出典・信頼度を `WordResource.source` / `verified` に転記。信頼度 ✅ は `verified=true` 候補、◎⚠❓ は M5 監修対象。
- パーサは規則を**注入可能 ruleset** として設計（§6）。ruleset は「使用可能な構文集合（解禁状態）」を表す。**未解禁構文は入力に出さない＝寛容判定しない。コア規則（格一致・語順）の合否は段階に依らず常に厳格。**
- **補助段階（§6.1）は UI 層（`04` SpellComposer）の責務で、`Validator` の合否・`G` には一切影響しない。** 文法は数値ステータスを持たない（D1）。`Validator` をテストする際、補助段階の状態を入力に含めないこと（疎結合）。
- 乱数は seed 管理（リプレイ・デバッグ・ローグライク再現性）。
- 旧辞典の MP/ターン値は**移植しない**（§0.2）。威力は `tier`、時間コストは `02`/`05` 側の世界時間モデルで扱う。
- **【最重要・移植禁止】旧辞典の効果語ダメージ式（`理解度値 × …`／`÷ 敵耐性値`／`− 敵防御値`）をそのまま実装しないこと。** 本作では理解度は**成功時の威力（`P_base`）には一切寄与しない**（威力ティアは理解度非依存：§1-1、§5.1、T1）。理解度が変えるのは「暴発の確率と質」だけ（§5.2/5.3）。結果として“敵に届く期待効果”は理解度とともに上がるが、それは**威力式に理解度を掛けるからではなく不発が減るから**——この区別を実装で守る。辞典の効果欄は「何が起きるか（害/治癒/弱体/移動）」の意味だけを抽出し、量的計算は §5 で再構築する。誤ると本作のテーマ（理解度＝制御／知識は残るが力は残らない）が崩壊する。

## 附録B. フィードバック文言テンプレ（日英・§7）

UI 文言はロケール別（`gloss` と同じ運用：JA 先行・EN リリース必須、`05`/`01` 6.1）。`{...}` はランタイム差込（語ID・推奨格・C値等）。実装は文言キー＋差込で i18n テーブル化（`04` i18n）。下記は雛形（最終文言はプレイテストで調整）。

### B.1 文法由来（格不一致など・全 C 帯で出る是正情報）
| 状況 | JA | EN |
|------|----|----|
| 目的語が対格でない | `{word} は対格ではありません（{suggest}？）` | `{word} is not accusative — did you mean {suggest}?` |
| 語順が正準形から逸脱 | `語順が乱れています。効果が安定しません` | `Word order is off; the effect won't hold steady.` |
| 条件節が不完全（ストレッチ） | `ef の後の条件が読めません` | `The condition after "ef" is unreadable.` |

### B.2 暴発・理解度由来（§5.3 バンド別。質を区別する）
| バンド | JA | EN |
|--------|----|----|
| ≤30 発動失敗 | `術が形にならなかった（不発）。この語の理解が浅い（C≈{c}）` | `The spell never took shape (fizzle). Your grasp of this word is shallow (C≈{c}).` |
| 31–60 実行失敗 | `術はほどけた——狙いがそれた／威力が落ちた（C≈{c}）` | `The spell unraveled — it veered off / weakened (C≈{c}).` |
