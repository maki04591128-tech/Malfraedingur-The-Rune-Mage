## 0. なぜこの文書が要るか

`02`（アジャイル計画）の鉄則は「コアが面白いと確認できるまで先に進まない」。だが「面白い」は曖昧語なので、**観測可能な基準**と**それを観測できるツール（spell_lab）の仕様**を先に固定する。これが無いと「なんとなく良さそう」で先に進み、後で破綻する。

検証する仮説（`02` INC-1）:

> **H: 「文法（格）を直すと呪文の手応えが目に見えて良くなる」のは、繰り返したくなるほど面白い。**

H が偽なら、`02` §4 の方向転換（文法スコープ縮小／コア再設計）をここで即決する。**戦闘・コンテンツには進まない。**

---

## 1. 2種類の検証を分ける（重要）

| | 自動テスト（正しさ） | 手動検証（面白さ） |
|---|---|---|
| 何を見る | 数式が仕様通りか | 触って繰り返したくなるか |
| 方法 | `03` §5.5 の不変条件 T1〜T5 を GUT 等で緑に | 開発者自身が spell_lab を遊ぶ＋可能なら他者 |
| 合否 | 機械的（緑/赤） | §4 の体験基準＋kill 基準 |
| 失敗時 | バグ修正 | スコープ縮小／再設計（`02` §4） |

**正しさが緑でも面白くなければ H は偽。** spell_lab は後者（面白さ）を判定するための道具。

## 2. spell_lab が表示すべきもの（UI 仕様）

`debug/spell_lab.tscn`（`04` §5）。戦闘なし。1画面で以下を出す。

### 2.1 入力
- 語タイル列ビルダー（`Lexicon` の全語を選べる。INC-1 はコア語彙＝効果語＋対象語＋四大元素）。
- 対象語タイルの**格サブ選択**（主格/対格…）。
- 生テキスト入力欄（無辞書モード相当の経路も同画面で試せる）。
- `C`（理解度）を**スライダで任意設定**（0–100）。実データ蓄積を待たず任意の理解度で挙動を見るため。
- ruleset 切替（入門/初級…相当の可用性。INC-1 は格一致 ON 固定でよい）。

### 2.2 単発結果パネル（1回詠唱）
`SpellEngine.cast()` の `CastResult` を**全部見える化**:
- `GrammarReport`: 規則ごと pass/fail ＋ 理由 ＋ **推奨修正**（例:「対格ではありません: `fjandi` → `fjanda`?」）。
- `P_base`（成功時威力天井）、`C`、`G`、`Control`。
- `p_misfire`（= clamp(0.10 − 0.001·C, 0, 0.10) の実値）。
- `C` がどの**重篤度バンド**か（≤30 発動失敗／31–60 実行失敗／61–99 制御失敗／100 なし）。
- 今回の解決結果（成功/暴発、暴発ならカテゴリと再解釈後の効果）。

### 2.3 バッチ結果パネル（N 回シミュレート）★最重要
暴発・ぶれは確率事象。**単発では手応えを判定できない**。「同じ呪文を N=200 回」ボタンで:
- 暴発率（実測 vs 理論 `p_misfire`）。
- 暴発カテゴリの内訳（不発/対象ズレ/自爆…のヒストグラム）。
- `effect_power` の分布（平均が `P_base` 付近に出るか＝T1 の体感確認）。
- 「格を直す前 / 直した後」を**横並び比較**で同時表示（H の核心：差が一目で分かるか）。

### 2.4 チューニングパネル（ライブ編集）
`05` BalanceConfig をその場で編集して即反映:
- `misfire.base_at_zero` / `decay_per_comprehension`
- `variance.v_max_by_tier` / `j_max_by_tier`
- `control.w_comprehension` / `w_grammar`、`word_order_bonus`
- `misfire.params`（power_drop_range / self_damage_ratio）

→ 「**どう調整しても面白くならない**」のか「**チューニングで面白くなる**」のかを判定するため。kill 判断の前に必ずチューニングを試す。

## 3. 必須テストシナリオ（毎セッション走らせる固定セット）

開発者は毎回これらを spell_lab で再現し、§4 の基準で評価する。

| ID | 入力 | C | 期待される観測（質的） |
|----|------|---|------------------------|
| S1 | `meiða fjanda`（対格・正） vs `meiða fjandi`（主格・誤） | 50 | 正は狙い通り命中、誤は弱く外れ、`GrammarReport` が `fjandi→fjanda` を提示。**差が即分かる** |
| S2 | S1 を C=0 / 50 / 100 で | 各 | C 上昇で暴発率が 10%→5%→0% に低下。暴発の質が不発→実行失敗→自爆へ重篤化 |
| S3 | 強ティア未習語を含む正しい呪文 | 0 | 成功すれば高威力だが約10%暴発・暴発時は不発（軽傷）。「博打感」が成立するか |
| S4 | 文法正・C 高 | 90 | ほぼ決定的。稀な暴発は自爆。達人の緊張感が出るか |
| S5 | 無辞書経路で語形を綴り誤り | 50 | タイル経路と同じ判定に正規化されるか（`03` §4） |
| S6 | 語順崩し（正準形から外す） | 50 | 語順ボーナス消失が威力に出る。崩しすぎの体感 |

シナリオは `tests/scenarios/*.json` 等で固定化し、ワンクリック再現できること（再現性＝seed 固定、`03` §8）。

## 4. 面白さの合否基準（H の判定）

§3 を触った上で、開発者（可能なら他者2〜3名）が以下を評価する。**数値ではなく体験**を見る。

### 4.1 通過条件（すべて満たす）
1. **発見可能性**: 説明なしで S1 を触り、「誤を正に直すと良くなる」と**5分以内に自力で気づく**。
2. **手応えの可視性**: 格を直した瞬間、結果の改善が**1〜2回の試行で体感できる**（バッチ比較で差が明白）。
3. **是正の有用性**: `GrammarReport` の推奨修正が「次どうすればいいか」を**実際に教えている**（迷子にならない）。
4. **戦略的緊張**: S3/S4 で「強い未習語を博打で撃つ／安全な既習語で堅実に」の**選択に迷いが生じる**。
5. **反復意欲**: 「もう一回最適化したい」と**自然に手が伸びる**（指示なしで複数回試す）。

### 4.2 計測（主観を記録する）
- 「最初の正しい呪文」までの時間（目標 < 5分、`01` 8章と整合）。
- 各観点を 5 段階自己申告（1=退屈 5=やめられない）。中央値で見る。
- 他者テスト時、声に出して操作してもらい「なぜそうした」を記録（思考の可視化）。

### 4.3 kill 基準（H が偽の判定）
次のいずれかが、**チューニングパネルで調整を尽くしても**該当する場合、H は偽:
- 通過条件 1〜2 が満たせない（差が分からない/気づけない）。
- 4.2 の中央値が 2 以下が支配的。
- 「直す作業が面倒なだけで楽しくない」という反応が多数。

→ `02` §4 の方向転換を即決：(a) 文法スコープを縮小（格一致以外を削る）して再検証、(b) それでも偽ならコアメカニクス再設計。**この時点で曲げるのが本ゲートの目的**。コンテンツ・戦闘には進まない。

## 5. 進行判断（このゲートの出口）

| 結果 | 次アクション |
|------|--------------|
| 自動テスト緑 ＋ §4.1 全通過 | INC-2（戦闘の手応え）へ進む |

## 6. INC-3.5 における新仕様での H 再判定（v0.2 追加）

`02 v0.9` で新設された **INC-3.5** は、範囲語・方向語をコア違反扱いに格上げした上で本 §3 シナリオ S1〜S6 と `08` C1〜C5 を再走し、H/H2 が新仕様でも成立するか確認する。本章は INC-3.5 実装時に走らせる再判定手順を規定する。

### 6.1 なぜ再判定が要るか

INC-1 v0.17 完了時点で H は真（207 アサーション緑、ユーザー実機で「文法を直すと手応えが出る」確認済み）。だがそれは **位置なし・範囲語/方向語なし** での話。`03 v0.18` で範囲語（`nær`/`fjarri`/`í gegnum`/`vítt`）・方向語（`fram`/`aptr`/`vinstri`/`hœgri`）がコアに昇格し、Validator が新たに `range_required` / `range_conflict` / `direction_required` の 3 規則を判定する状態で、認知負荷増（タイル選択＋格選択＋位置移動＋射程判断＋方向指定）が S1 の核心「**5 分以内に自力で気づく**」を破綻させていないかを観測する必要がある。

これは `01` の元議論（v0.3 で「コアはグリッド非依存」と却下した根拠）が現実化していないかの直接的検証。

### 6.2 再判定の前提条件

- INC-3 まで通過済み（シームレス戦闘の最小実装が安定動作）。
- `03 v0.18` の文法判定が実装済み（spell_builder で範囲語・方向語の minor finding が表示される）。
- `09 §9` の scaffold=max 射程プレビューが実装済み（タイルハイライト・方向矢印・AoE 範囲）。
- INC-3.5 で MISFIRE_MULT_BY_RULE が拡張済み（`range_required=2`/`range_conflict=3`/`direction_required=2` を `BalanceConfig` 経由で有効化）。

### 6.3 再走するシナリオ

§3 の S1〜S6 を **位置あり・範囲語/方向語ありの状態で再走**する。具体的には:

| ID | 元仕様 | INC-3.5 再走時の修正 | 期待される新観測 |
|----|--------|------------------------|------------------|
| S1 | `meiða fjanda` vs `meiða fjandi` | 隣接タイルに敵を 1 体配置。詠唱は方向語なし → 最隣接敵自動選択 | 位置あり状態でも「格を直すと手応え変化」が変わらず体感できるか |
| S2 | C=0/50/100 | 同上 + 各 C で 10 回詠唱 | 暴発カテゴリが理解度のみで変わる不変条件 T3 が新仕様でも成立するか |
| S3 | 強ティア未習語 | 同上、範囲語追加 `vítt meiða fjanda` も試す | AoE 倍率が掛からない方針（`09 §7.4` 暫定）で「強い AoE が強すぎ／弱すぎ」が体感されるか |
| S4 | 文法正・C 高 | 方向語 `fram meiða fjanda` を C=90 で 5 回 | 達人状態で方向語ミス（`fram` を `aptr`）した時の威力減衰が `G` 線形乗算（T6）通りか |

| S6 | 語順崩し | 範囲語・方向語混在の語順崩し（`meiða nær fram fjanda`） | word_order ×6 が範囲語・方向語の位置誤りにも適用されるか |

加えて **新規シナリオ S7〜S9** を追加（INC-3.5 で `tests/scenarios/spell_inc35/` に固定化）:

| ID | 状況 | 期待 |
|----|------|------|
| S7 | 射程外 (`nær` 指定だが対象がマンハッタン距離 3) | range_required finding、ダメージ 0、UI が「届かない」を提示 |
| S8 | 矛盾 (`nær fjarri meiða fjanda`) | range_conflict finding、暴発 ×3 で重篤化 |
| S9 | 方向欠落 (`vítt meiða fjanda` で方向語・タイル指定なし) | direction_required finding、scaffold=max は事前ブロック / それ以下は詠唱不可 |

### 6.4 通過条件（新仕様 H 真の判定）

§4.1 の元 5 条件に加え、以下を新規追加。**全条件を新仕様でも満たす**ことが H 真の判定基準。

1. **§4.1.1 発見可能性（5 分以内）の維持**: scaffold=max（射程プレビューあり）で、説明なしに S1 を触り、「誤を正に直すと良くなる」を 5 分以内に自力で気づく。**位置あり状態で初学者が「方向指定で混乱して 5 分超える」を起こさない**こと。
2. **§4.1.2 手応えの可視性の維持**: 格を直した瞬間、結果の改善が 1〜2 回の試行で体感できる。位置あり詠唱が GrammarReport の可読性を下げていないこと。
3. **新規 H 拡張**: S7〜S9 で「届かない／矛盾／方向欠落」のフィードバックが「次どうすればいいか」を実際に教えている。
4. **新規 H 拡張**: scaffold=max の射程プレビューが「事前に間違いに気づける」補助として機能している（被験者が詠唱前にタイルハイライトを見て呪文を修正する動きをする）。

### 6.5 kill 基準（新仕様 H が偽の判定）

§4.3 の元 kill 基準に加え、以下のいずれか該当で H は新仕様で偽:

- **§6.4.1 (5 分以内発見) が破綻**: scaffold=max でも 10 分以上かかる被験者が多数。「タイル選択＋格選択は分かったが方向指定で詰まった」の反応が多い。
- **§6.4.2 (手応えの可視性) が破綻**: 「位置あり詠唱になってから GrammarReport が複雑すぎて読めない」「画面の情報量が多すぎる」の反応が多い。
- **scaffold=max の射程プレビューが UI 上で機能していない**（プレビュー実装は正しいが認知的に活用されていない）。

→ `02 §4` の方向転換: (a) 範囲語・方向語を「初級+」以降に後ろ倒し（入門段階は方向語なしで素手感覚で戦う）、(b) scaffold=max の補助 UI を再設計、(c) どうしても破綻するなら**マス目移動・グリッド戦術自体を撤回**し `01 v0.3` の「グリッド非依存」に戻す判断もあり得る（最後の手段）。

### 6.6 結果の記録

再判定の結果は本書の §6.7（次バージョン v0.3 で追加予定）に記録する。書き込み項目:

- 各被験者の S1〜S9 通過/未通過、5 分以内発見の達成有無
- 5 段階自己申告の中央値（§4.2 と同形式）
