## 0. なぜこの文書が要るか

`02` §3 INC-2 の学び目標は **「コアの気持ちよさを第三者が触って言語化できるか」**。INC-1 では `spell_lab`/`spell_builder` で「文法を直すと手応えが良くなる」までは確認できたが、それは **戦闘の文脈なし** での話。戦闘 UI・ターン・敵 HP・世界時間 Δ が乗った瞬間に、INC-1 の手応えが消える/見えづらくなる可能性がある。

検証する仮説（H2）:

> **H2: 「呪文を組んで敵に当て、誤射の原因が分かり、次の詠唱で改善できる」体験は、INC-1 の手応えを戦闘層でも失わずに増幅する。**

具体的サブ仮説:
- H2a: 詠唱→ダメージ→敵 HP 減のフィードバックが、`GrammarReport` 単独より「やった」感を強める。
- H2b: 誤射時、戦闘 UI 上でも「なぜ外れた／弱かった」が即わかる。原因が「敵が悪い」ではなく「自分の文法が悪い」と帰責される。
- H2c: 雑魚 1 体 → ボス 1 体の最小プログレッションが「もう一回」を生む。

H2 が偽（戦闘層で手応えが消える）なら、`02` §4 の方向転換：戦闘 UI の見せ方を再設計するか、INC-1 の枠組み自体を再考。**INC-3（7日ループ）には進まない。**

## 1. 機能要件（combat_test の UI/挙動）

`scenes/combat/combat_test.tscn`（新設）。`spell_builder` の上に戦闘層を被せる構造。

### 1.1 戦闘エンティティ
- **Player**: HP（既定 100）、習得語の一覧、scaffold_level 設定。
- **Enemy（雑魚）**: HP（既定 30〜50）、属性耐性（任意）、`AttackPattern`（ターン経過で固定ダメージを Player に返す簡易 AI で十分）。
- **Boss**: HP（既定 120）、属性耐性あり、複数攻撃パターン（INC-2 はパターン 2 種で十分）。

### 1.2 ターン構造（`01` 3.8 準拠）
- プレイヤーターン: 「呪文を 1 つ構築して詠唱」or「待機/学習」を選ぶ → 解決 → 敵ターン。
- 1 詠唱 = 1 プレイヤーターン + 世界時間 Δ（語数 × 基本コスト + ティア加算、`05` `cast_cost`/`world_time_costs` に従う。INC-2 では Δ を表示するだけで使用効果は無くてよい — INC-3 への接続点として可視化する）。
- 敵ターン: 固定 AI で Player.hp を削る。

### 1.3 詠唱解決経路
- 既存 `SpellEngine.cast()` の `CastResult` を再利用。
- 新規 `DamageCalculator`: `effect_power` と element/chaos と Enemy.resist から最終ダメージを計算（最小: `damage = effect_power × elem_mult × DAMAGE_SCALE`、`elem_mult` は雑魚 1.0 固定でも可）。
- **v0.2 補正: `DAMAGE_SCALE = 3.0`**。実機検証で P_base ~ 2.3 vs 敵 HP 30 / Player HP 100 が釣り合わず、雑魚撃破 13+ ターンに対し Player は雑魚反撃 8 ダメ × 12 ターンで死亡することが判明。全戦闘ダメージを底上げして「文法 OK で 3〜5 ターンで雑魚撃破」できる強度に揃える。INC-3 で `BalanceConfig.damage_scale` に外出し予定（現状は `core/combat/damage_calculator.gd` const）。
- **v0.2 特例: sjalfr (自己対象) 経路は DAMAGE_SCALE を掛けない**。誤詠唱で対象タイルを取り違えたとき即死級ダメを受けるのは「文法を試す心理的コスト」を上げすぎる。タイル選択ミスは比較的明確な誤りなので、ペナルティはマイルドに保つ。
- 暴発時の挙動（`03` §5.3 重篤度バンド）を **戦闘層に反映**：
  - 不発 (≤30): ダメージ 0、ターンは消費。
  - 実行失敗 (31–60): ダメージ × 0.5、対象外（隣にいる味方/自分なし時は宙に消える）。
  - 自爆 (61–99): Player.hp に self_damage_ratio × effect_power を加算（DAMAGE_SCALE 適用）。
  - 100 (達人): 暴発しない（INC-1 と整合）。

### 1.4 UI 表示
- HP バー（Player / 現在敵）。
- ターン表示（「あなたのターン / 敵のターン / ターン N」）。
- 詠唱ログ（直近 N 件: 入力呪文 / `GrammarReport` 要約 / ダメージ / 暴発カテゴリ）。
- 世界時間 Δ の累積表示。
- scaffold_level による補助 UI（INC-1 の仕様をそのまま戦闘層に持ち込む）:
  - **max**: ライブプレビュー + ダメージ予測表示。
  - **mid**: ヒント + 詠唱前確認ダイアログ。
  - **low**: 既存（詠唱後にレポート）。
  - **none**: GrammarReport を簡略化（合否のみ）。

### 1.5 進行
- 雑魚 1 体撃破 → Boss 出現 → Boss 撃破 → 「フロアクリア」表示 + 経過ターン数 + 累積 Δ + 詠唱回数を表示。
- Player.hp 0 → 「敗北」表示 + 同統計（INC-3 で巻き戻しに置き換える前提の暫定出口）。
- **v0.2 残課題: ボス出現演出が不足**。雑魚撃破時に「ボス Helgrind 番人が現れた！」のような戦闘ログ強調＋HP バー色変化＋一時停止のいずれかが必要。現状は HP バーが切り替わるだけで「次の段階に進んだ」感が薄い。
- **v0.2 残課題: 暴発演出が不足**。暴発カテゴリ別に色分けやアイコンが欲しい。`activation`=灰／`execution`=黄／`control`=赤 など。実機検証では C=50 base=5% でなかなか暴発しないので、まず scaffold_low の C=0 で意図的に踏むテストが必要。

### 1.6 リセット
- 「最初から」ボタンでフロア初期化（INC-3 の巻き戻し未実装の代替）。

### 1.8 v0.4 で追加された周辺機能（spell_builder と同水準）

- **ruleset OptionButton**: phase_intro / phase_beginner / phase_intermediate / phase_advanced を即切替。scaffold_level の差分を combat 文脈で観察できる（§4.1.1 と §4.1.5 の前提）。
- **C (理解度) HSlider**: 0–100 を実データ蓄積を待たず任意設定。INC-1 の spell_lab と同思想。
- **シナリオ OptionButton**: `tests/scenarios/combat/index.json` から C1〜C5 を自動ロード。選択で ruleset_id / scaffold_level / c_override / enemies.hp/atk / tokens を一括適用してフロアリセット。これにより §3 必須シナリオが「ワンクリックで再現」できる（08 §3 と整合）。
- **チューニングパネル (CheckButton 開閉)**: DAMAGE_SCALE / 雑魚HP / 雑魚ATK / ボスHP / ボスATK のスライダ。`DAMAGE_SCALE` だけは `DamageCalculator.DAMAGE_SCALE = v` で即時反映。敵パラメータは「最初から」で反映（フロア生成時に読み取るため）。
- **ボス出現演出**: `_on_enemy_defeated` ハンドラで雑魚 (index=0) 撃破時に「⚔ ボス出現: <名前>」を戦闘ログへ目立つ赤で出力。ボスの HP/ATK もログに併記。敵名ラベルもボス色（濃赤）に切替。
- **暴発演出**: カテゴリ別の色＋アイコン: `activation`=灰○ / `execution`=橙◇ / `control`=赤✸。暴発時のみログに目立つ行が追加される。意図的に C=0 + scaffold=none で踏むと確認可。

### 1.7 v0.2 で確認済みの動作（実機検証 2026-05-23）
combat_test.tscn を Godot 4.6.2 で起動し、phase_intro (scaffold=mid, C=50 デフォルト) で以下を確認:

1. **正詠唱 (`meiða fjanda`, acc)**: 文法 OK / G=1.00 / Δ=3.0 / 命中 → 敵 2.3 ダメ。HP バー連動 OK。雑魚反撃 8 ダメ。ターン進行 OK。
2. **誤詠唱 (`meiða fjandi`, nom)**: 文法 NG / G=0.50 / 命中 → 敵 1.2 ダメ（約半減）。戦闘ログに「✗ fjandi は対格ではありません → fjandi → fjanda ?」が表示される（INC-1 の GrammarReport が戦闘層でもそのまま機能する）。
3. **暴発判定**: C=50 base=5%, case×2 = 10% 確率で暴発しなかった（試行 2 回）。意図的に踏むには C=0 + scaffold=none が必要。v0.2 では確認まで至らず。

→ **H2a（フィードバックの増幅）は v0.2 時点で予備的に肯定**: GrammarReport の即時性 + HP バー減少 + ターン進行の組み合わせは、INC-1 の Report 単独より「やった/外した」が分かりやすい。ただし統計は試行 2 回のみ。C1〜C5 シナリオで正式判定する。

## 2. スコープ

### 2.1 含める
- 1 フロア = 雑魚 1 体 + ボス 1 体（02 §3 INC-2 通り）。
- コマンド入力型ターン制。
- 入門 + 初級ルール（`03` §6）の範囲: 効果語 + 対象語（4 格） + 四大元素 + 修飾語 mikill/litill。
- scaffold_level 4 段階の戦闘内切替（INC-1 と同じ実装をそのまま使う）。

### 2.2 含めない（INC-3 以降）
- 7 日ループ、巻き戻し、`öld renna aptr`。
- フロア生成（複数フロア）。
- 移動/探索（コマンドに「待機」だけ用意して接続点を作る）。
- 語彙発見、理解度上昇の 3 経路（INC-4）。
- セーブ/ロード。

### 2.3 統計信頼性
INC-1 と異なり、戦闘は **連続詠唱** で評価する。S1〜S5 を各 5 回ずつ通しでプレイして、(a) 雑魚撃破までの平均ターン数 (b) ボス撃破率 (c) 暴発回数の中央値 を記録する。N=200 のバッチは戦闘層には不要（Resolver 層の確率検証は INC-1 で済）。

## 4. 気持ちよさの合否基準（v0.3 確定）

### 4.1 通過条件（すべて満たす）

1. **発見可能性（戦闘版・C4 シナリオ）**: phase_intro (scaffold=max) + C=0 で説明なしに combat_test を渡し、雑魚 fjandi を **5 分以内に自力で撃破** できる。ライブプレビューの「✓ プレビュー: 文法 OK」を頼りに `meiða fjanda` を組めるか。
2. **手応えの可視性（C1 シナリオ）**: 正詠唱でダメージ + HP バー減少が、INC-1 の `GrammarReport` 単独より「やった」感を上回ると **開発者本人が言語化** できる。具体的には combat_test と spell_builder で同じ呪文を撃ち比べて、「戦闘の方が確かに気持ちいい」と即答できる。
3. **誤射→修正→命中のループ（C2 シナリオ）**: 文法 NG 詠唱後、戦闘ログの推奨修正を見て **次ターン以内に自力で正詠唱できる**。被験者が「fjandi → fjanda」の対応を口に出す。
4. **再挑戦意欲**: 敗北画面で **5 名中 3 名以上が「最初から」ボタンを自発的に押す**（一回で諦めない）。
5. **第三者言語化**: 開発者以外の被験者 **2 名以上が「面白い」「悔しい」「次はこうする」のいずれかを口に出す**（声に出す観察、`02` §0「学んだことを言語化」の戦闘層版）。

### 4.2 計測（記録項目）

- C1 で雑魚撃破までの平均ターン数（目標: 3〜6 ターン、`tests/scenarios/combat/c1_*.json` の expected_outcome）。
- C4 で「最初の正しい呪文」までの時間（目標 < 5 分、`01` 8 章・INC-1 §4 と整合）。
- C5 で暴発回数 (目標 0、達人不変条件 T6 が戦闘層でも保たれる確認)。
- 各観点を 5 段階自己申告（1=退屈 5=やめられない）。中央値で見る。

### 4.3 kill 基準（H2 が偽の判定）

次のいずれかが、**v0.2 の DAMAGE_SCALE 含むチューニングを尽くしても**該当する場合、H2 は偽:

- **§4.1.1 (発見可能性) が満たせない**: scaffold=max でも 5 分以内に雑魚撃破できない被験者が多数（コアが自明でない）。
- **§4.1.2 (手応えの可視性) が満たせない**: 「戦闘 UI を被せても spell_builder と感じが変わらない」または「戦闘 UI のせいで GrammarReport が見えづらくなった」と感じる。
- **誤射の帰責が「ゲームのせい」になる**: 暴発時に被験者が「ゲームが理不尽」と感じる（「自分の文法が悪かった」ではなく）。
- **第三者が要約で言語学要素を落とす**: 被験者が「タイル選んでボタン押すだけ」と要約する（古ノルド語の格・語順を意識しない）。

→ `02` §4 の方向転換: (a) 戦闘 UI のフィードバックを再設計、(b) DAMAGE_SCALE/HP のバランスを大幅変更、(c) それでも偽なら INC-1 の枠組み自体（C・G・暴発の関係）に立ち戻る。**INC-3（7 日ループ）には進まない**。
